# JavaScript SDK

The JavaScript family owns browser authentication and Node.js framework integrations.
This page's integration examples describe the **current unpublished source candidate**.
The manifest version `0.1.0` does not identify that candidate, and older `0.1.0` preview tarballs do not
automatically contain its transaction, account-security or invitation APIs.

## Install the current candidate

Obtain approved matching core/framework tarballs built from the reviewed source commit.
Set the variables below to those actual artifact paths, then install core and the framework you use:

```bash
# React
npm install "$VERTEX_CORE_TARBALL" "$VERTEX_REACT_TARBALL"
# Express
npm install "$VERTEX_CORE_TARBALL" "$VERTEX_EXPRESS_TARBALL"
# NestJS
npm install "$VERTEX_CORE_TARBALL" "$VERTEX_NESTJS_TARBALL"
```

These are artifact-path variables, not registry package names or ready-made downloads.
No current npm release is claimed here. The
[source integration map](https://github.com/axis-iam/vertex-sdk-js/blob/develop/docs/current-integration.md)
links to the matching package guides.

## React SPA quickstart — current candidate

Create a `SPA` public ApplicationClient with an exact callback, logout URI, and allowed origin.

```tsx
import {IamProvider, SignIn, useAuth} from '@axis-iam/vertex-react';

function Session() {
  const {isAuthenticated, user, logout} = useAuth();
  if (!isAuthenticated) return <SignIn />;
  return <button onClick={() => void logout({redirect: true})}>Sign out {user?.name}</button>;
}

export function App() {
  return (
    <IamProvider
      issuerUri="https://auth.example.com"
      clientId="your-spa-public-client-id"
      redirectUri="https://app.example.com/callback"
      postLogoutRedirectUri="https://app.example.com/signed-out"
    >
      <Session />
    </IamProvider>
  );
}
```

The provider uses Authorization Code + S256 PKCE and keeps tokens in memory by default. Browser code never receives a
client secret. Use `@axis-iam/vertex/server`, Express, NestJS, or React server exports only in server runtimes with a
WEB/M2M confidential client.

## Browser configuration

| Provider value | Portal source | Rule |
| --- | --- | --- |
| `issuerUri` | Vertex public Auth URL | HTTPS base URL, with no API path |
| `clientId` | **Clients** -> SPA client ID | Public `ApplicationClient.clientId`, never the Application UUID |
| `redirectUri` | SPA redirect URI | Exact allowlisted callback |
| `postLogoutRedirectUri` | SPA post-logout URI | Exact allowlisted URI |
| `audience` | Application resource audience | API identifier, not a client ID |
| `tokenStorage` | Application decision | Memory by default; opt in to `sessionStorage` only after accepting its XSS risk |

### Hosted redirect and callback

Hosted is the default browser mode. It sends the user to the Vertex-hosted page and returns through the SPA callback.

```tsx
import {SignIn} from '@axis-iam/vertex-react';

export function LoginPage() {
  return <SignIn mode="redirect" />;
}
```

On the registered callback route, call `useAuth().handleRedirectCallback({cleanUrl: '/callback'})` once for the
current callback, consume any promise rejection, and handle every result:

| `status` | Application behavior |
| --- | --- |
| `success` | OAuth exchange and authenticated views completed; continue into the application |
| `session` | A configured server-session flow completed; continue into the application |
| `continuation` | Preserve the returned `transaction` and `view`; render the required MFA step |
| `error` | Show the returned error and a deliberate sign-in retry |
| `idle` | No consumable callback is present; offer the sign-in entry instead of an indefinite spinner |

For `continuation`, no session has been issued. Render the offered MFA proof and use
`transaction.verifyMfa('TOTP', code)` or the offered recovery-code method, then
`client.completeAuthentication(transaction)` through `useAuth().client` when the returned view permits completion.
The lower-level transaction method takes **method, code**; the `useAuthFlow` action takes **code, method**.
Alternatively, let the [Custom form flow](../../authentication/custom/) own Provider callback resumption using
`actions.resumeProviderCallback(url)`. Do not have both consumers process the same callback.
The [React package guide](https://github.com/axis-iam/vertex-sdk-js/blob/develop/packages/react/README.md)
describes Provider return, MFA and callback ownership.

An invitation popup uses a passive callback consumed by its opener, rather than this standalone callback handler.

### Embedded

Embedded keeps password and passwordless UI inside the application. The SDK discovers enabled and runtime-ready
methods in the Application identified by the SPA client. Policy stays Application-owned.
Credential proof and required MFA share a controlled transaction, followed by OAuth code exchange with S256 PKCE;
refresh also uses OAuth. Do not call retired Direct login/refresh endpoints.

```tsx
<SignIn mode="embedded" onSuccess={() => window.location.assign('/')} />
```

Email OTP signs in an existing active Application user. Signup is a separate `SignUp mode="embedded"` flow and must
follow the Application signup mode, email-verification policy, and optional registration-grant contract.

### Prebuilt Dialog

Dialog is a controlled presentation of the same Hosted or Embedded engines, not a third authentication protocol.

```tsx
import {useState} from 'react';
import {AuthDialog, SignInButton} from '@axis-iam/vertex-react';

export function AuthEntry() {
  const [open, setOpen] = useState(false);
  return (
    <AuthDialog open={open} onOpenChange={setOpen} mode="embedded" allowSignUp>
      <SignInButton>Sign in</SignInButton>
    </AuthDialog>
  );
}
```

Use `mode="redirect"` when the dialog should open the Hosted flow. In redirect mode, login and ordinary open signup
share one hosted entry; do not add decorative tabs that lead to the same route.

## Node.js resource server

Node APIs use a different WEB/M2M confidential client under the same Application. The browser sends its bearer access
token to the API; Express verifies the token and resolves current permissions through Vertex.

```ts
import express from 'express';
import {permKey} from '@axis-iam/vertex';
import {iamAuth, requirePerm} from '@axis-iam/vertex-express';

const app = express();
app.use(iamAuth({
  endpoint: process.env.IAM_ENDPOINT!,
  clientId: process.env.IAM_CLIENT_ID!,
  clientSecret: process.env.IAM_CLIENT_SECRET!,
  resourceAudience: process.env.IAM_RESOURCE_AUDIENCE!,
}));
app.get('/orders', requirePerm(permKey('orders', 'read')), (_request, response) => {
  response.json({orders: []});
});
```

`IAM_CLIENT_ID` and `IAM_CLIENT_SECRET` here belong to the server client, not the SPA. Use a separate exact-scope M2M
client for Portal Open API management; never call management APIs from browser code.
