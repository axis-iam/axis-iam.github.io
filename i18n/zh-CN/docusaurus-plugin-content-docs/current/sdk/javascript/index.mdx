# JavaScript SDK

JavaScript SDK 提供浏览器认证、React 界面与 Node.js 框架集成。
本文示例与生成参考基于[源码清单](pathname:///source-revisions.json)记录的已提交版本。

需要把 Token 留在应用后端时，使用可选 [BFF 服务端会话接入](./bff/)，本文原有示例继续用于浏览器 Token／Bearer。

## 从源码安装

从同一提交构建配套的 core 与框架包。本文使用 Node.js 24 和 pnpm 11.9.0。
这些包目前未发布到 npm；在应用中安装下面构建出的本地产物。

```bash
git clone https://github.com/axis-iam/vertex-sdk-js.git
cd vertex-sdk-js
git checkout 21bccfc0079474aa655efbaddc1331b30c83e928
pnpm install --frozen-lockfile
pnpm --filter @axis-iam/vertex-react... build
mkdir -p artifacts
pnpm --dir packages/core pack --out ../../artifacts/vertex-core.tgz
pnpm --dir packages/react pack --out ../../artifacts/vertex-react.tgz
```

在应用目录安装两个产物，按实际克隆位置调整相对路径：

```bash
npm install ../vertex-sdk-js/artifacts/vertex-core.tgz ../vertex-sdk-js/artifacts/vertex-react.tgz
```

Express 同样构建打包 core 和 `packages/express`。NestJS 另外依赖同版 Express 包，
需要一起安装 core、Express、Nest 制品，详见 [BFF 包接线](./bff/)。框架包不能替代 core。

## React SPA 快速入门

```tsx
import {IamProvider, SignIn, useAuth} from '@axis-iam/vertex-react';

function Session() {
  const {isAuthenticated, user, logout} = useAuth();
  if (!isAuthenticated) return <SignIn />;
  return <button onClick={() => void logout({redirect: true})}>Sign out {user?.name}</button>;
}

export function App() {
  return (
    <IamProvider
      issuerUri="https://auth.example.com"
      clientId="your-spa-public-client-id"
      redirectUri="https://app.example.com/callback"
      postLogoutRedirectUri="https://app.example.com/signed-out"
    >
      <Session />
    </IamProvider>
  );
}
```

Provider 使用 Authorization Code + S256 PKCE，并默认把令牌保存在内存中。浏览器代码不会接收 client secret。`@axis-iam/vertex/server`、Express 或 NestJS 仅用于配置 WEB/M2M 机密客户端的服务端运行环境。

## 浏览器配置

| Provider 值 | Portal 来源 | 规则 |
| --- | --- | --- |
| `issuerUri` | Vertex 公网 Auth URL | HTTPS 根地址，不带 API path |
| `clientId` | **客户端** -> SPA client ID | 公开 `ApplicationClient.clientId`，不是 Application UUID |
| `redirectUri` | SPA redirect URI | 必须与 allowlist 精确一致 |
| `postLogoutRedirectUri` | SPA post-logout URI | 必须与 allowlist 精确一致 |
| `audience` | Application resource audience | API 标识，不是 client ID |
| `tokenStorage` | 接入应用自行决策 | 默认 memory；只有接受 XSS 风险后才显式选择 `sessionStorage` |

### Hosted redirect 与 callback

Hosted 是默认浏览器模式，用户进入 Vertex 托管页，并通过 SPA callback 返回。

```tsx
import {SignIn} from '@axis-iam/vertex-react';

export function LoginPage() {
  return <SignIn mode="redirect" />;
}
```

在登记的回调路由中，对当前回调仅调用一次 `useAuth().handleRedirectCallback({cleanUrl: '/callback'})`，
处理 promise 拒绝，并覆盖所有结果：

| `status` | 应用处理 |
| --- | --- |
| `success` | OAuth 交换与已认证视图加载完成，进入应用 |
| `session` | 已配置的服务端会话流程完成，进入应用 |
| `continuation` | 保留返回的 `transaction`、`view`，显示必需的 MFA 步骤 |
| `error` | 显示返回错误，提供明确的重新登录操作 |
| `idle` | 当前没有可消费的回调，提供登录入口，不要一直显示加载 |

`continuation` 不代表会话已经签发。展示当前允许的 MFA 证明方式，调用
`transaction.verifyMfa('TOTP', code)` 或允许的恢复码方式，
返回视图允许完成时，再通过 `useAuth().client` 调用 `client.completeAuthentication(transaction)`。
底层事务方法的参数顺序是**方式、验证码**，`useAuthFlow` action 的顺序则是**验证码、方式**。
Custom 表单的第三方返回默认由 `useAuthFlow` 自动恢复；不要再让 Hosted 回调处理器消费同一返回。
完整返回、MFA 与回调归属要求见
[React 包接入说明](https://github.com/axis-iam/vertex-sdk-js/blob/21bccfc0079474aa655efbaddc1331b30c83e928/packages/react/README.md)。

邀请独立窗口使用由发起窗口消费的被动回调页，不使用这里的独立回调处理器。

### Embedded

Embedded 把密码与 passwordless UI 放在接入应用内。SDK 通过 SPA client 定位 Application，
发现已经启用且 runtime-ready 的方式，策略仍归 Application 所有。
凭据证明、必需 MFA 保持在同一受控事务中，再通过 S256 PKCE 交换 OAuth 授权码；刷新也走 OAuth。


```tsx
<SignIn mode="embedded" onSuccess={() => window.location.assign('/')} />
```

邮箱验证码只登录当前 Application 中已有的 active 用户。注册使用独立的 `SignUp mode="embedded"`，并遵守
Application 的注册模式、邮箱验证策略和可选 registration grant 合同。

### 预制 Dialog

Dialog 只是对同一套 Hosted/Embedded engine 的受控展示，不是第三种认证协议。

```tsx
import {useState} from 'react';
import {AuthDialog, SignInButton} from '@axis-iam/vertex-react';

export function AuthEntry() {
  const [open, setOpen] = useState(false);
  return (
    <AuthDialog open={open} onOpenChange={setOpen} mode="embedded" allowSignUp>
      <SignInButton>登录</SignInButton>
    </AuthDialog>
  );
}
```

需要托管流程时使用 `mode="redirect"`。redirect 模式中的登录和普通公开注册共用一个 Hosted 入口，不要增加
两个最终进入同一路由的装饰性 Tab。

## Node.js 资源服务器

Node API 使用同一 Application 下另一个 WEB/M2M 机密 client。浏览器把 bearer access token 发给 API；Express
校验令牌，并通过 Vertex 解析当前权限。

```ts
import express from 'express';
import {permKey} from '@axis-iam/vertex';
import {iamAuth, requirePerm} from '@axis-iam/vertex-express';

const app = express();
app.use(iamAuth({
  endpoint: process.env.IAM_ENDPOINT!,
  clientId: process.env.IAM_CLIENT_ID!,
  clientSecret: process.env.IAM_CLIENT_SECRET!,
  resourceAudience: process.env.IAM_RESOURCE_AUDIENCE!,
}));
app.get('/orders', requirePerm(permKey('orders', 'read')), (_request, response) => {
  response.json({orders: []});
});
```

这里的 `IAM_CLIENT_ID` 与 `IAM_CLIENT_SECRET` 属于服务端 client，不是 SPA。Portal Open API 管理使用另一个
具备精确 scope 的 M2M client；浏览器不得调用管理 API。
