# 快速入门

本流程在同一个 Application 下创建浏览器客户端与机密资源服务器客户端。

## 1. 创建 Application

在 Vertex Portal 中创建 Application，并设置资源 audience，例如 `api://orders`。资源服务器校验访问令牌的 `aud` 时使用该标识；它不是 Application UUID。

## 2. 创建 ApplicationClient

| 运行环境 | 客户端类型 | 密钥 | 必需控制 |
| --- | --- | --- | --- |
| 浏览器 SPA | `SPA` | 无 | 精确重定向 URI、登出 URI、允许 origin、Authorization Code + S256 PKCE |
| 原生应用 | `NATIVE` | 无 | 精确重定向 URI、Authorization Code + S256 PKCE |
| Web/BFF | `WEB` | 必需 | 服务端保存密钥；交互式 code flow 使用 S256 PKCE |
| 服务/Worker | `M2M` | 必需 | 服务端保存密钥并请求精确 scope |

SDK 配置中的 `clientId` 始终指 `ApplicationClient.clientId`，而不是内部记录 UUID。不要把 WEB 或 M2M 密钥放入浏览器代码。

## 3. 配置回调

注册应用实际使用的精确回调与登出 URL。不要依赖通配回调主机或隐式推导 origin；SPA 还需要注册精确的浏览器 origin。

## 4. 完成认证

若希望最小化浏览器安全责任，请使用 [Hosted 认证](../authentication/hosted/)；
需要应用内界面时，选择 [Embedded](../authentication/embedded/)、
[Dialog](../authentication/dialog/) 或 [Custom](../authentication/custom/)。
Hosted 使用 Authorization Code + S256 PKCE。Embedded、Custom 将凭据证明和必需 MFA 保持在同一受控认证事务中，
再使用原 PKCE 绑定通过 OAuth 交换事务完成后返回的授权码。Dialog 呈现所选 Hosted 或 Embedded 流程。
刷新使用 OAuth，不再接入旧 Direct 登录或刷新端点。

认证策略归属于 Application，`clientId` 仅定位其客户端，不代表独立的 Client 级策略。
注册与登录分开；注册完成或邮箱验证成功，不会自动建立登录会话。

## 5. 保护 API

API 校验签名、issuer、audience、有效期与 ApplicationClient 上下文，然后通过 `POST /open/v1/permissions:resolve` 将令牌角色解析为当前权限；不要信任过期的权限 claim。

继续阅读 [JavaScript 快速入门](../sdk/javascript/)，或服务端的 [Java](../sdk/java/)、[Go](../sdk/go/) 与 [Python](../sdk/python/) 快速入门。
接入前确认对应 SDK 的安装与发布边界，当前 JavaScript 源码中的新 API 并不一定包含在旧 preview 包中。
配置真实 Application、客户端、策略、身份提供商和回调时，请使用[新应用接入清单](./connect-application/)。
