# Hosted 认证

Hosted 认证将浏览器重定向到 Vertex authorization endpoint。Vertex 在自身 origin 上负责凭据输入、身份提供商选择、加强认证挑战和策略错误；应用负责发起请求、保存 OAuth state 与 PKCE verifier、校验回调并建立自身 UI 状态。

## 浏览器流程

1. 生成不可预测的 `state` 与 PKCE verifier。
2. 派生 S256 challenge，并为 SPA 公开客户端发起授权。
3. Vertex 完成用户认证，将 authorization code 返回精确注册的 URI。
4. 校验 `state`，用 verifier 交换 code，并移除回调参数。
5. 仅向目标资源 audience 发送访问令牌。

Hosted SPA 中不得出现 client secret。WEB/BFF 在服务端使用密钥与 PKCE verifier 完成交换。

在 `IamProvider` 内使用 `<SignIn mode="redirect" />` 或 `useAuth().login()`，
不必手工实现上述协议步骤。登记的独立回调页使用 `handleRedirectCallback`，
明确处理成功、错误、无回调和可能的继续认证结果，见
[JavaScript 回调说明](../../sdk/javascript/)。
邀请独立窗口的回调由发起窗口消费，因此使用被动回调页。

托管页通过已配置客户端解析目标 Application 的品牌和策略。页面位于 Vertex 域名，
不代表它变成通用控制台登录，也不改变 Application 对认证策略的归属。
